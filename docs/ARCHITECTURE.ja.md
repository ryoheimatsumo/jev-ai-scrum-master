# アーキテクチャ

[English](ARCHITECTURE.md)

現在のα版の構成を説明します。目標仕様にあるすべての機能の実装を意味しません。

## 役割分担

| 構成要素 | 担当 |
|---|---|
| Skill・ホストLLM | プロジェクト情報を調べ、計画・実装・改善案を作ります。 |
| CLI | ホストとの構造化入出力と、明示的なローカルの人間操作を提供します。 |
| Core・SQLite | 契約、改訂、承認、有限の再試行、証拠の鮮度、DONE資格を管理します。 |
| Runner | コピーした入力に対し、登録済みチェックを実行して、上限付きの結果を保存します。 |
| Jevアダプター | 任意の限定的な分類。質問の版管理とキャッシュを持ちます。 |
| MCPアダプター | 同じCoreへの別の入口です。独立した判定ルールは持ちません。 |

Skillは常時監視する独立エージェントではなく、ホストが呼び出す必要があります。
Coreの完了判定は、ホストの全終了やGit操作に対するフックではありません。フックは自動導入しません。

## 検証

タスクには受け入れ基準とチェック・ケースの対応を持つ、版付きの契約があります。人間が現行の契約を承認し、
エージェントが実装します。Runnerが承認済みチェックを実行し、結果を契約と内容スナップショットへひもづけます。
未コミット・未追跡の入力も対象です。

必須結果が0件、skip、欠損、古い、未レビューの場合は完了資格を満たしません。
コマンドの正常終了だけで、任意の動作が正しいとは扱いません。
standardタスクでは現在、人間がassertionと証拠の対応をレビューします。
読み取り専用の自動AIレビューは目標機能であり、まだ利用できません。

Jevは証拠の関連候補を示せますが、PASS、権限、承認は変更できません。最終gateは資格を再計算します。
DONEは本ツールの現行契約を満たした意味であり、未知の不具合がない証明ではありません。

## 状態と機密性

状態はプロジェクト外に置きます。Linuxでは`XDG_STATE_HOME`または`~/.local/state`、macOSでは
`~/Library/Application Support`の配下に、ワークスペース別の`jev-sm`ディレクトリを使います。
実際の場所は`doctor`で確認してください。入力用の計画・ログは検証対象ソース外に置きます。

SQLiteで改訂と冪等な要求を管理します。助言キャッシュはCLI終了後も保持し、承認・実行証拠とは分離します。
キャッシュには生プロンプトを残しません。使用量が分からない場合は0ではなく不明として扱います。
ホストの全処理を計測するものではありません。

作業ツリーのコピーや環境変数の最小化はOS・ネットワークのサンドボックスではありません。
全依存関係の指紋、同一ユーザーの敵対的処理の隔離、クラッシュ復旧には制限があります。[安全性](../SECURITY.ja.md)。

## 配布と言語

実行用Skillの正本は`src/jev_sm/assets/skills/jev-scrum-master`です。
`skills/jev-scrum-master`へ同期し、配布側にはwheelと整合性manifestも含めます。
英語と日本語で競合する実行用Skillを作らず、人向け文書を二言語化し、実行契約とIDは一つの正本で管理します。

人向け文書は[一覧](README.ja.md)から辿れます。目標仕様とADRは当時の設計判断を残すもので、
現在使える機能は[実装状況](IMPLEMENTATION_STATUS.ja.md)で確認してください。
文書だけの更新は、α版の実行機能の更新やホスト互換性の実証を意味しません。
