# Jevの設定と助言コマンド

[English](JEV.md)

標準SkillはCLIを呼び出すため、MCPサーバーは不要です。Jevは任意で利用する外部APIです。
無効でも、Coreによるチェック、レビュー、証拠、完了条件の管理は利用できます。

## 送信内容を確認してから有効にする

ソースから導入した場合は、CLIと同じ環境に任意の依存関係を追加します。

```sh
python -m pip install -e '.[jev]'
```

同梱版では、Skillのランチャーを通じてJev SDKの準備内容を確認し、セットアップを依頼します。
`TYPESAFE_API_KEY`は自分の環境に設定し、チャット、Skill本文、Git、プロジェクトYAMLには書きません。
送信可能なコード・ログの抜粋を確認し、`.jev-sm/config.yaml`の`jev_enabled`を`true`にします。
SDKを導入しただけでは通信は有効になりません。設定変更後は、既存タスクの計画を確認して再承認します。

Coreは送信前に既知の秘密値のマスクを試みますが、完全なDLPではありません。
コーディングホスト側のデータ管理とは別です。[セキュリティ](../SECURITY.ja.md)。

## コマンドの意味

TASKには実際のIDが必要です。対象Gitルートで実行するか、サブコマンドの前に`--repo`を指定します。
入力用ファイルは、検証対象のソーススナップショット外に置いてください。

```sh
jev-sm advise readiness TASK
jev-sm advise playbook TASK --observation-file /OUTSIDE/REPO/observed.txt
jev-sm select-context TASK --input /OUTSIDE/REPO/context.json
jev-sm advise evidence TASK
jev-sm cache stats
```

| コマンド | 意味 |
|---|---|
| `advise readiness` | 計画の不足と、基準の結果を観測できるかを分類します。 |
| `advise playbook` | 継続、最小再現・環境・保存・契約の調査、人間への確認、保留などを提案します。 |
| `select-context` | 関連情報を選ぶ助言です。必須情報や判断不能な情報は残します。 |
| `advise evidence` | 登録された証拠と受け入れ基準の関係を候補として示します。 |
| `cache stats` | 助言キャッシュの状態を確認します。テスト網羅率や完成度ではありません。 |

入力形式は`schema context`で確認します。受け入れ基準、制約、重大な失敗は`mandatory: true`を付け、
必要なときに再取得できるよう原文を保持してください。件数は文字数であり、実測トークン数ではありません。
精度・速度・ホストのトークン削減は保証しません。Jevは限定された選択肢を評価し、計画・説明・コードはホストが作ります。

## 障害と権限

判断不能、低confidence、API利用不能は助言の状態であり、チェックを省略する許可ではありません。
Jevの回答だけでPASS、人間専用操作の承認、計画の緩和、タスク完了は行えません。
confidenceは観測された正答率ではありません。必要なレビューは維持します。

## キャッシュ

既定は86,400秒、ワークスペース当たり最大512件です。`jev-X.Y.Z`の明示的なモデル版だけを対象とし、
`jev-latest`などの別名は対象外です。キーにはタスク、契約、設定、backend・モデル、質問の版と内容、入力ハッシュを含みます。
失敗は保存しません。キャッシュには元入力のハッシュを使い、生のプロンプトとしては保存しません。

ヒットは、その助言に新しいAPI呼び出しが不要だった意味であり、検証を実施した意味ではありません。
PASS、承認、実行証拠をキャッシュで代替しません。同時の初回要求では呼び出しが重複し得ます。
プロセス間の予算の原子的な予約は未実装です。

`jev_cache_ttl_seconds: 0`または`jev_cache_max_entries: 0`で無効にできます。

```sh
jev-sm cache clear
jev-sm cache clear --write
```

最初はプレビュー、後者は助言キャッシュの削除です。証拠や判断履歴は削除しません。
a2より前のタスクは、正規化される設定既定値の変更に伴い、確認と再承認が必要です。

ミューテーションテストや質問の自動最適化は[残作業](BACKLOG.ja.md)であり、これらのコマンドで
使える隠れた機能ではありません。
