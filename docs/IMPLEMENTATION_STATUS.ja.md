## 実装済みの縦断経路

計画スキーマ → 出典/契約/設定の版固定 → 人間のTTY承認 → 開始 →
分離したコードコピーで実際のチェック実行 → 受け入れ条件別の確認 →
人間による代替レビュー → 完了gate → 改善提案/承認。

ホストLLMが計画・分割・実装・自由文の振り返りを行う。ツール単独がコードを生成する
自律エージェントではない。作業単位はタスクで、同一worktreeでは同時に1件だけ。

## Jevを利用する経路

- readiness: 同じ計画に対する独立した不足/観測可能性の質問を一括処理。
- playbook: 継続/最小再現/環境/保存/契約/人間判断/不明の手順候補を選択。
- context_selection: 必須・不明な情報を保持し、無関係の強い候補だけ退避。原文は呼出元で保持。
- evidence_relation: ACとRunner証拠の関連候補を評価。これだけではPASSにしない。
- 入出力スキーマ、低confidenceの保留、状態/モデル/質問版ハッシュ、メモリキャッシュ、
  logical backend呼出数/利用量/時間の記録。HTTP再試行数とホスト全体トークンはunknown。
- MCPのstatusは要約。証拠はハッシュ検証後に必要範囲だけ追加取得する。

外部送信は既定無効。実APIは未実行。速度・精度・総費用・トークン削減効果は未測定。
